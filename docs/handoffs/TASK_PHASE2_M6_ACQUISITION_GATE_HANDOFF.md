## 4. Architecture and Design Decisions

Proposed new Bronze dataset identity:
`iex-1min-pilot-msft-nvda-jpm-xom-20260914-v1`. The acquisition UUID will be newly
generated by the existing runner. Exact provider parameters will be:

```text
symbols=MSFT,NVDA,JPM,XOM
start=2026-09-14T13:30:00+00:00
end=2026-09-14T19:59:59.999999+00:00
asof=2026-09-14
feed=iex
timeframe=1Min
adjustment=raw
limit=10000
sort=asc
```

This is a read-only market-data request to the fixed Alpaca data endpoint. It makes
no trading request. The four requested symbols have 1,560 scheduled symbol-minutes,
below the 10,000-bar page limit, so one successful terminal page is expected if all
scheduled bars exist. Missing bars are permitted and will not be filled. Provider
pagination is still honored if returned.

Planned policy: 15-second timeout, three attempts per page, five-page ceiling.
Therefore the absolute request ceiling is 15 HTTP attempts. The maximum accumulated
socket-timeout budget is 225 seconds. Retry-After is bounded to 30 seconds; across
five pages and two retry waits per page the maximum retry-wait budget is 300 seconds.
The combined theoretical timeout-plus-wait ceiling is 525 seconds. Retriable states
are 429, 500, 502, 503, 504 and transport failure; other HTTP statuses fail closed.
Repeated response bodies, repeated continuation tokens and page-limit exhaustion
also fail closed.

Credentials remain process-environment only through `ALPACA_API_KEY` and
`ALPACA_API_SECRET`. The current Codex process reports both as absent. No credential
file or external credential store was searched, and no value was displayed.
